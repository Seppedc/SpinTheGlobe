# Detective Workshop skill tree

`DefaultSkillTree.asset` defines 39 cash-funded skills: ten ranks each of Momentum (Speed), Auto-Motor and Pincraft (Durability), plus three restoration tiers for each existing figurine. `SkillTreePanel.prefab` contains the reusable UI and internal callbacks. Its manager reference is intentionally empty; OnEnable resolves the existing manager. The scene panel has an explicit manager reference.

Progress comes directly from GameManager's existing levels and FigurinePedestal.Tier. No extra currency, inventory, purchase store, save format or reset was introduced. Existing levels are grandfathered as owned even if a newly configured prerequisite is absent. Selection only inspects; Unlock calls PurchaseSkill, which delegates to the original purchase/effect functions. Direct legacy callbacks obey the same gates.

Costs remain in the unchanged `Gameplay/Data/UpgradeConfig.asset`: ceil(base * growth^(rank-1)); Speed base 75, Motor 100, Durability 60, Restoration 120, growth 1.8 (existing float precision), engineering maximum 10. Restoration multipliers remain 1 / 1.5 / 2 / 3 and sum across the three original figurines. IDs map to existing effects: `speed_01` through `speed_10`, `motor_01` through `motor_10`, `durability_01` through `durability_10`; `figure_<index>_<tier>` uses figure indices 0–2 and tiers 1–3.

Each engineering rank requires its previous rank. Motor ranks 3+ also require Momentum floor((rank-1)/2). Pincraft ranks 3+ also require Motor floor(rank/3). Restoration tier 1 requires Pincraft 1; tier 2 requires its previous tier and Motor 1; tier 3 requires its previous tier and Momentum 3. All first engineering ranks are accessible from the free visual foundation. Restoration links to other tabs have labeled source markers; complete requirements are shown in the detail pane.

To modify a graph, edit the ScriptableObject nodes: stable unique ID, title, description, existing effect mapping, rank, prerequisite IDs, position and tab. Keep exactly one node per effect/rank and preserve existing IDs. Call Validate before assignment and run DetectiveDesk.Editor.SkillTreeGraphValidation.Run in Edit Mode. Changes to the graph do not rebuild serialized UI automatically: update the matching card, callback and connector references inside the panel and reusable prefab. SkillTreeIntegration.Build is a one-time installer that refuses an existing content child; Finish applies the scoped final layout/prefab refinements. Do not rerun initial GameplayIntegration.Setup.

The original Upgrades modal and close/open/Escape bindings remain. Its original Gameplay controls object remains inactive with references and callbacks retained. Engineering has a bounded vertical ScrollRect reaching rank 10; Restorations has a separate retained scroll position. Nodes remain selectable while locked. Money changes from both GameManager events and legacy case rewards refresh affordability.

Opt-in validation: SkillTreeGraphValidation.Run (25 production graph/purchase checks), SkillTreeRuntimeValidation.Arm (77 checks over real Play frames and callbacks), original GameplayRuntimeValidation.Arm (126 unchanged regression checks), and SkillTreePreservationValidation.Run. Evidence and 1920×1080 captures are in ProductionLogs/SkillTree. Play harnesses use temporary runtime cash/progress and leave Edit Mode state untouched. Physical mouse and keyboard Escape events were not synthesized; original bindings/source, callback events, UI bounds and world-input guard were checked. No assets were generated with Blender or image generation.

Open the tree with the visible UPGRADES button beside Archive. Clicking a figurine opens its restoration path directly. This scene entry uses the existing ToggleUpgrades callback; it does not replace Archive or change the other HUD controls. SkillTreeEntryIntegration.Install is a one-time helper and refuses duplicate installation. Its opt-in Arm check tests the actual UI ray and callbacks, then restores Edit Mode without storing test money. Additional proof: ProductionLogs/SkillTree/entry-runtime-validation.json and entry-preservation-validation.json.
